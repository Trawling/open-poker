# Как внести вклад в Open Poker

*(This project's documentation is currently in Russian. An English
translation is a very welcome first contribution — see "Куда можно
приложить руки" below.)*

Спасибо, что заинтересовались! Этот проект живёт по тем же принципам,
что и Lichess для шахмат: бесплатно, без рекламы, без реальных денег,
открытый код. Прежде чем предлагать изменения, стоит прочитать
`docs/00-overview.md` (зачем вообще этот проект) и `research/02-legal.md`
(почему принципиально нет реальных денег — это не временное ограничение).

## Неизменные правила проекта

Эти пункты — не технические детали, а причина, по которой проект вообще
может легально существовать как бесплатный открытый сервис. PR, нарушающие
их, закрываются без обсуждения:

1. **Никаких реальных денег.** Нельзя покупать фишки за деньги, нельзя
   обменивать фишки обратно на деньги или что-то ценное. Как только это
   появляется — сервис юридически становится нелицензированным казино
   почти везде в мире (см. `research/02-legal.md`).
2. **Никакой рекламы и трекинга пользователей.** Донаты на инфраструктуру —
   можно (как у Lichess), но они не должны влиять на игровой процесс
   (никакого pay-to-win, никаких платных преимуществ).
3. **Обязательная регистрация для игры — нет.** Можно *добавлять*
   опциональные возможности поверх гостевого режима, но зайти и сыграть
   без единого лишнего шага должно оставаться возможным всегда.

## Как запустить проект локально

```bash
git clone <url-вашего-форка>
cd open-poker
npm install
npm run dev
```

Откройте http://localhost:5173. Подробности — в `README.md` и
`docs/03-implementation-notes.md` (что уже реализовано, что нет, почему).

## Как проверить, что ничего не сломалось

```bash
npm run test                        # тесты движка (комбинации, сайд-поты, честность, equity)
node scripts/smoke-test.mjs         # сквозной прогон раздачи через реальный WebSocket-протокол
node scripts/persistence-test.mjs   # проверка, что стек переживает перезапуск backend-процесса
```

Если меняете логику движка (`packages/engine`) — добавьте тест рядом в
`packages/engine/test/`. Для бэкенда/фронтенда формальных e2e-тестов пока
нет (это как раз хорошая первая задача, см. ниже) — проверяйте вручную
через `npm run dev` и/или smoke-скрипты.

## Структура репозитория

См. `docs/03-implementation-notes.md` — там расписано, что лежит в
`packages/engine`, `backend`, `frontend` и зачем.

## Стиль кода

- TypeScript везде, `strict: true`, без `any` без крайней необходимости.
- Комментарии — только там, где код неочевиден (почему, а не что). Смотрите
  на плотность комментариев в соседних файлах и придерживайтесь её.
- Коммиты и PR-описания — на русском или английском, как удобнее.
- Перед PR: `npm run test` должен проходить, новый код — собираться
  (`npm run build -w <пакет>`).

## Процесс

- **Маленький фикс / явный баг** — смело открывайте PR напрямую.
- **Новая фича или заметное изменение поведения** — сначала откройте issue
  с описанием идеи, чтобы не переписывать работу впустую, если подход не
  подойдёт.
- Открывая PR, вы соглашаетесь, что ваш вклад распространяется под той же
  лицензией, что и весь проект — **AGPL-3.0-or-later** (см. `LICENSE`).
  Отдельного CLA подписывать не нужно.

## Куда можно приложить руки прямо сейчас

Честный список открытых хвостов — подробнее в
`docs/03-implementation-notes.md`:

- **Перевод документации на английский** — чтобы проект был понятен не
  только русскоязычным контрибьюторам.
- **E2E-тесты фронтенда** (Playwright) — сейчас есть только
  `scripts/smoke-test.mjs` без браузера.
- **Усиление бота** — текущий использует Монте-Карло equity + пот-оддсы
  (`backend/src/bot.ts`), это всё ещё далеко не GTO.
- **Реальная проверка Docker-сборки** — `docker-compose.yml` и Dockerfile'ы
  написаны и вручную провалидированы пошагово, но не собирались в
  настоящем Docker (см. `docs/04-deploy.md`) — если у вас есть Docker,
  протестируйте `docker compose up --build` и пришлите фикс, если что-то
  не так.
- **Визуальный дизайн** — текущий интерфейс рабочий и минималистичный, но
  не является финальным визуальным языком проекта.
- **Полноценные аккаунты** вместо нынешнего лёгкого «кода личности»
  (`frontend/src/lib/identity.ts`) — если захочется сделать это без потери
  духа «зашёл и сразу играешь».

## Кодекс поведения

Коротко: будьте доброжелательны. Обсуждайте код и идеи, а не людей.
Токсичное поведение, оскорбления и дискриминация — повод для бана в
issue/PR без предупреждений.
